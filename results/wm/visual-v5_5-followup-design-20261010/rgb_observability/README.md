# V5.5 已知 RGB 可观测性诊断

固定颜色质心规则能从原始两帧 RGB 恢复绝大多数运动，栅格化不是现有大幅错向的充分解释。这是事后、使用渲染器颜色身份知识的特权诊断，不是编码器性能，也不是新的通过门槛。

全部 Dev640–895、两个 variant（512 episodes）的 t6/t7 原始图像逐个重绘：1024 RGB 数组的 shape/dtype/SHA256 与旧归档完全一致，512 个标签和顺序逐项一致。没有运行编码器、训练或访问 Test。仅重绘两个已评估 cue，没有生成未来帧。

## 预测规则与固定评价

主规则在每个 RGB 中取 A 的 R=235/B=60 像素、B 的 R=60/B=235 像素，各自计算所有匹配像素的算术质心。预测末帧位置及两帧质心差。预测函数不读取 latent 位置、目标真值、renderer masks 或每例随机 green 色值。颜色语义来自已知生成器，故明确属于特权 oracle。白色描边与内部横线/十字不匹配颜色规则，会给质心带来微小偏差。

辅助检查是同一组颜色像素的 min/max 边框中点；它始终列为辅助，不按结果优劣选择。两种规则均无需参数拟合。

所有 skill 分母精确使用旧 V5.4 冻结模型 `shared_target_mean`，与 V5.5 一致，不使用 Dev 均值/方差。完整8维均值保存在 report.json 与 predictions.npz；其运动4维恰好为0。归档 global/lane 分数独立复算匹配。

| 固定读出 | 水平 dx MSE（归一化坐标） | 水平 dx RMSE（像素） | 四维平均 motion skill |
|---|---:|---:|---:|
| RGB颜色质心（主） | 0.00000323977549 | 0.40319 | 0.98098289 |
| RGB颜色边框中点（辅助） | 0.00000225059352 | 0.33604 | 0.98712726 |
| global W | 0.00011845535721 | 2.43795 | 0.43399918 |
| lane W | 0.00008317713032 | 2.04291 | 0.57994665 |

像素值是归一化坐标乘224。水平主指标只平均 A_dx/B_dx，四维 motion skill 另外包含两个 dy；两者不可混称。

## 栅格化与方向

标签是连续反射位置 p7−p6（最后转为FP32），不是光栅中心之差，也不是未经反射的 velocity。椭圆边界经过 int 截断，绘制的 glyph 也落在离散像素，所以会有量化误差。质心逐轴运动 RMSE 为0.373/0.399/0.431/0.406像素；辅助边框为0.336/0.338/0.337/0.316像素。该误差是这两个诊断器的实际误差，不是 Bayes 最优下界。

按固定的像素分辨率界限分列（本次为事后诊断，不是预注册检验）：zero 当归档位移恰为0；tiny 当 0<|位移×224|<1；大于等于1像素另列。不排除任何例子。四轴 tiny 数分别为2/17/0/14，共33/2048；恰零为0。主质心的11个严格反向与2个零预测全部发生在 tiny 组。其余2015个至少1像素的运动坐标方向全部正确。global/lane在此组分别仍有351/262个方向错误。

两帧之间发生反射的轴计数为6/52/4/38；原标签已经正确计入反射的净位移。反射可造成小净位移，但不是标签误用原速度。

## 可见性和身份边界

原 cue 时间为6和7，两个 shutter 均打开。目标半径.06、A中心y∈[.15,.40]、B中心y∈[.60,.85]，其轮廓与黄色y∈[.48,.52]不相交；横向也没有画布裁剪。1024幅重绘图均通过mask不重叠检查，每个目标都有340–410个可见颜色像素。A/B有不同固定红/蓝通道及横线/十字，同时位于不同竖直区域，因此当前两对象的身份没有必须交换的对称歧义。

在这1024幅图/512个两帧输入中，没有发现相同RGB对应不同连续位置，也没有相同两帧输入对应不同标签；也没有单个episode两cue完全相同。有限样本无碰撞不代表连续标签全局可精确辨识：从连续状态到有限整数像素的渲染在数学上必然多对一，微小位移仍可能不可见。当前可观测性结果不能证明编码器保存了这些线索，也不能确定丢失发生于encoder、pooling还是reader。

## 可证伪的下一步控制（未执行）

固定保存RGB oracle的逐例残差作为像素分辨率参考，对现有神经预测同时报告连续latent标签与预先固定的可见中心位移标签：若神经错向仍大量存在于RGB oracle方向正确且≥1像素的坐标，纯栅格化解释被否定；若错误集中于tiny或oracle失败坐标，则应先处理标签可观测性。不要以辅助bbox表现更优为由改主规则，也不要把oracle语义身份信息当成普通无监督视觉模型的可用条件。

要进一步区分encoder与pooling，需要同一次编码、相同像素输入上的固定raw/pool读出对照及匹配FIT；当前高RGB分数本身不能完成该模块归因。

## 复现

使用运行记录中的同一 Pillow 11.3.0。输出目录需为新目录，已有结果不会被覆盖。

```bash
/Library/Developer/CommandLineTools/usr/bin/python3 results/wm/visual-v5_5-followup-design-20261010/rgb_observability/audit_rgb.py \
  --scene execution/visual-v5_4-20261010/diagnostic-20261010-v54 \
  --v55 execution/visual-v5_5-20261010 \
  --out /tmp/v55-rgb-observability-reproduction
```

`per_episode_coordinate.csv` 包含512×4行完整真值/预测、tiny分组与反射标记；`frame_hashes_and_centers.json` 包含1024幅图的核对哈希和RGB中心；`predictions.npz` 保留原始八维输出、标签、pair/variant顺序及冻结均值。report.json、input_inventory.json记录源码、输入哈希、环境和实际命令。未修改任何旧场景或科学源文件。
