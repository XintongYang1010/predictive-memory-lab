# 网页端机制与新方向审阅

来自用户授权的对话「分支 · Saining Lec6&实验」。Turn `9de245b2-24d0-4d3f-afe2-c5bc59f2e7e0`，reply `e00c9bb5-5986-5c1d-a296-555ee2ce9837`。回复当时 fresh64 尚未完成；本地后续结果另见最终报告。以下为审阅原文，不作为实验结果或执行指令。

已回读 [5243d6 的 CPU 报告](https://github.com/XintongYang1010/predictive-memory-lab/tree/5243d6474eeb0f4be14e2dfe640ebe4161547861/results/wm/visual-v5_6-20261010)。单轴部分以下依据你提供的实测回执，尚未核验 GPU 逐例归档。

**目前最有解释力的假说是：读出没有建立稳定的“对象—二维位移”对应，而是在使用随场景、位置和上下文变化的特征相似性。** 正确区域的细节能帮助恢复运动；但场景中其他变化、甚至同一对象的纵向变化，也会投射到水平输出。这是关于当前表示与读出组合的假说，不是 encoder 单独失效的结论。

| 环节 | 当前证据支持什么 | 尚不能认定什么 |
|---|---|---|
| 对象干扰 | 正确区域访问在共同尺度、df 控制后仍有效，空间对齐有实质作用 | 已学会对象身份，或收益全部来自排除另一对象 |
| 轴串扰 | 其他对象和黄条固定时，纯 y 仍产生 false-x；加入 y 能改变 x 的预测方向 | 串扰一定产生于 encoder，或所有 xy 交互都有害 |
| Encoder contextualization | 黄色变化可以通过不直接覆盖黄色的外侧 token 影响读出 | 上下文本身就是错误，或这些 token 已没有目标信息 |
| Reader geometry | 本轮标量 df 修正不够；特征访问结构和对应规则会明显改变表现 | 所有正则解释均已排除，或 pooled 信息不可恢复 |

单轴结果尤其重要：**对象分开以后，对象内部的坐标解码仍可能出错。** 因而继续只裁空间区域，未必能解决剩余问题。

同时，correct→wrong 与 wrong→correct 都存在，说明纵向变化有时破坏水平预测，有时补偿原有偏差。lane 的 false-x/interaction RMS 更大，也不能直接称为轴选择性更差——自身响应同时增强，方向翻转还取决于预测距零的余量。不能把这些 RMS 当责任比例，也不宜据此直接删除全部跨轴特征交互。

我会把下一轮方向收敛到两个具体方案。

1. **用共享的二维对应读出，替代依赖布局的直接位移回归。**

   对每个对象构造局部二维位移代价面 \(C(\delta_x,\delta_y)\)，匹配参数跨位置、跨对象共享，输出以实际像素位移为坐标。内部仍允许联合二维建模；约束应放在**输出对物理干预的响应**上：

   - 只移动 A 的 y，A 的 dx 应保持零。
   - 改变 B 或黄色，A 的位移预测应尽量保持。
   - A 真正沿 x 移动时，预测必须保留方向和幅度，不能靠整体收缩满足前两条。

   最小公平比较应先固定同一表示、同一 bank、同一访问区域和 FIT，比较现有核读出与这种共享对应读出；raw/pool 作为独立因素，避免同时更换所有环节。颜色 ROI 继续只作特权诊断参照，不能冒充已经解决对象发现。

   **可证伪预测：**在新数据上，非目标响应和 pure-y false-x 下降，同时 x-only 与完整二维运动的误差、幅度保持或改善。若只有负控变小而真实运动被压没，或者收益仅限已见布局，就没有支持所声称的对应机制。

   当前 raw/ROI 对 891/1 B 恢复了方向，但仍只预测约 `+1.5px`、真值为 `+3.348px`，正说明“保留细节”之后仍有解码问题。[逐例证据](https://github.com/XintongYang1010/predictive-memory-lab/blob/5243d6474eeb0f4be14e2dfe640ebe4161547861/results/wm/visual-v5_6-20261010/correspondence_interpretation/README.md)

2. **按目标预测价值分配细节预算，先把保存选择与写入门控拆开。**

   保留“四个粗描述子＋十二个细节描述子”的固定预算，让选择器学习：**哪些位置的细节会改善目标运动或下一状态预测**。训练监督可以来自 FIT 中不同合法 bank 对预测误差的影响；实际选择只能使用当前观测、已有历史和任务查询，不能读取未来帧、真值 mask 或执行预置红蓝规则。

   第一阶段固定 reader 和 FIFO，只改变细节选择。这能检验 learned selector 是否真正接近特权 ROI 的收益，而不把选择、解码和门控的变化混在一起。

   **可证伪预测：**相同字节预算下，它在新场景中优于 uniform/random；黄条变得更显著时仍保留目标所需细节，并改善实际预测。若只是提高目标 footprint 覆盖、预测没有改善，或只能复现固定颜色/上下区域规则，就没有证明任务相关选择成功。

   写入门控应在这之后单独研究。当前 q95 范数门控漏掉真实变化，表明该标量不是本次条件下可靠的更新依据；后续可以检验由对象对应产生的状态改变量和覆盖旧状态的风险，但不能直接把匹配峰值锐度叫作可信度，更不能用降阈值修饰本轮阴性结果。

这两个方向的区别是：**第一个研究怎样正确读出运动，第二个研究有限预算该保留哪些证据。** 当前特权 ROI 为第二个方向提供了可行示例，尚未提供无特权方案。

J/X fresh64 仍值得按原协议完成：它直接检验对象组合监督，尚未给对象内部的 dx/dy 独立变化提供监督。即使 J/X 成功，也不能据此宣布轴串扰或长期 memory 问题已经解决。
