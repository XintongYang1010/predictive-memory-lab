## Reproduction boundaries and documentation gaps

1. **Full re-extraction has an explicit prior-archive dependency.** The new scene copies the frozen reader and prior predictions, but does not duplicate the old bridge feature cache, old bridge receipt/shards, original FIT cache, or prior full manifest. The extractor's original-input provenance guard requires the old bridge files. `dependencies.json` names release `visual-v5_1-20261010` at https://github.com/XintongYang1010/predictive-memory-lab/releases/tag/visual-v5_1-20261010 and pins the prior scene manifest SHA256 `56d35d072c7d8a885429902c7128572b645e4040a47e5edf0347177f03f1f6ae`. Retrieve that dependency to reproduce extraction or refitting; it is unnecessary for replaying this saved reader from the included new feature cache.
2. **Official encoder assets are external.** The roughly 10 GB checkpoint and I-JEPA source checkout are not duplicated. Their checkpoint SHA256 and official code commit are recorded in the receipt and worker records. Raw RGB/mask arrays are represented by their hashes and deterministic generator metadata/source; reproducing those pixels requires rerendering with the recorded original generator. This is an identified dependency, not an assertion that the archive contains the external weights or raster images.
3. **The generic requirements file is not the measured environment.** Archived `code/requirements.txt` pins NumPy 1.26.4, whereas the actual extraction receipt records Python 3.11.15, NumPy 2.4.6, Torch 2.8.0+cu128, and CUDA 12.8. The V5.2 extraction receipt does not record Pillow's version, even though PIL rasterization participates in the input guard. The separately saved preflight recorded Pillow 12.3.0. Reproduction documentation should name that measured environment and include the preflight evidence in the curated result package; do not describe `pip install -r requirements.txt` as an exact recreation. The sealed scene should remain unchanged.
4. **Recorded commands contain the original absolute remote paths.** For a local CPU replay, redirect `--cache` and `--receipt` to the included `counterfactual_cache/`, `--model` to the included `reader/`, and `--prior-predictions` to `prior_bridge/predictions.npz`. Run the archived `code/scripts/score_v5_2_counterfactual.py`, choose a new output directory outside the sealed scene, and set `PYTHONDONTWRITEBYTECODE=1`. Do not rerun the original controller against its historical paths.

The archive therefore supports an independent frozen-prediction replay with its own included scientific inputs and model. End-to-end GPU regeneration is reproducible through the declared dependency chain and measured environment; it is not a single self-contained weight-and-environment bundle. The preserved scientific failures, unopened Test, and unchanged P0 authorization are accurately represented.
