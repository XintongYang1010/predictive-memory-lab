# 首周实验协议

## V3 特征与对照（当前协议）

V3 使用 31 维特征：前 14 维保留 V2 的瞬时摘要，12 维描述观测区间前后半段残差、
残差增长、当前坐标系中的纵横偏差、区间内方向一致性、上一更新残差、变化量、两次残差最小值、
跨更新误差方向对齐、历史证据有效性及区间覆盖。跨更新摘要来自实际策略经过的历史，
每个新场景清空；比较的是各次更新当时使用的 bank，不是追踪一个固定 bank 的长期误差。

最后 5 维来自当前观察下 Keep/Reset 的两个预测分布：概率加权均值轨迹差、终点差、
归一化轨迹空间中的对称 energy distance、残差×energy distance、探测可用标志。
两次探测从克隆的同一记忆开始，不写回真实状态，不读取 target 或 target_mask。
这些量描述输出敏感性，不能说明哪次预测更准确；收益监督仍只能来自 Train 的未来标签。
距离对预测模式独立重排保持不变；方向摘要使用当前局部坐标和世界向量夹角保证刚体变换不变。

`--ablation` 固定一轮，共享 Keep 产生的 Train/Dev 样本；base / temporal /
temporal_influence 三组屏蔽不同输入，使用相同 31→64→64→3 架构、初始化种子、
minibatch 随机序列、500 步默认预算和每组至多 3 个候选。base 是本轮控制组，
不保证与 V2 的 14→64 架构初始化或数值逐位一致。三组均执行 2 次探测/决策，
另报告无需探测的 Keep 和带相同探测的 keep_probe，所有 Rebuild 前向计入总成本。
并未实现轻量蒸馏后的无探测部署，也不主张提高了推理速度。

每组独立在 Dev 按原门槛固定模型，再一次性评价所有预定组；不按 Eval 选择获胜模型。
主输出 controller 是 temporal_influence；另外两组结果为 controller_base/controller_temporal。
候选的完整逐场景 Dev 记录、权重和哈希在 `.candidates/` 中保存；完成后自动从记录重算筛选。
选择的 CI 仍只是调参门槛，同一已查看过的 Eval 子集仍属于探索性分析。

V3 不接受 V1/V2 controller 或旧分支数据；必须重新收集新增的因果特征。
下面保留原方法定义和 V2/V2.1 演进背景，未说明变更的指标与门槛继续沿用。

## 可检验的问题

旧预测是否在新证据到达后拖累连续预测？选择性修正是否优于保留、全清空和匹配随机干预？一个不看未来的小 controller 是否能超过简单规则？这些都是待测假设。

## 运行状态

每个分支保存整个 RealMotion `memory_dict`，另保留上一时刻已观察输入窗口。
状态包括 scene encoder、模式特征、世界方向预测位移、场景/actor 有效性、origin、heading、timestamp、模式先验。
上游 `glo_y_hat` 实际是世界方向的相对位移；残差计算必须加上保存的 origin。
特征提取不执行上游“把旧预测平移到其预测当前位置”的重对齐。

新增证据是从 previous_step 到 current_step 的真实观测；未来预测部分不用于判错。
每次策略调用从保存的先验重新算一次权重，不把同一残差递归乘进 posterior。
没有有效重叠时，重加权和选择性删除退化为 Keep；controller 强制选择 Keep。
V2 在原 12 维特征后增加当前更新时间和上一 bank 是否使用过历史上下文的标志；二者都由已观察状态确定。
没有历史上下文的 bank 禁选 Rebuild；这使 4 秒更新的已知无效动作不会被选中。

## 分支监督

从当前策略诱导的每个更新前状态克隆四份完整状态。
在分支起点执行一次候选动作，后续沿用相同当前策略、相同真实观察日程和确定性局部随机种子。
比较公共绝对目标区间上的平均 ES。未来评分只发生在 `metrics.frame_scores`，不传回动作接口。

对于 4 秒事件，比较 4/5 秒两个更新；对于 5 秒事件，只比较当次输出。
因此不得把 5 秒事件称为“多步恢复实验”。各事件的动作比较严格配对，事件之间单列。

V2 分支还保存 5 秒更新后的完整 60 帧 `final` 指标。
收益回归目标为 `branch_keep.final.energy_score - branch_action.final.energy_score`，
用 MSE 监督 Reweight / Rebuild / Reset 的全部收益，包括负收益；Keep 的预测收益固定为零。
公共窗口产生的 `label/weight/tie` 保留为诊断字段，V2 不使用它们训练。

Train-repair 只负责梯度更新。Dev 先按已记录分支的平均实际收益对 checkpoint/门槛组合排序，
取最多 `--dev-candidates` 个决策不同的候选（默认 3），再在整个 Dev 中逐个完整运行。
候选每次更新使用自己产生的历史状态；选择指标与最终报告一致，都是完整 60 帧 ES。
预测收益门槛候选固定为 0.01 / 0.05 / 0.1 米。零干预候选由 Keep 基准覆盖。
配对场景 bootstrap CI 下界大于 0 且普通场景平均收益非负时才可入选，以平均收益选最终模型。
没有候选满足条件就回退 Keep。这个 CI 只作为开发集调参门槛，不能宣称筛选后的统计显著性。
完整候选记录、选中的 step/门槛与回退状态保存在 `roundN.controller.selection.json`。
Calibration 继续决定 sigma/tau/残差阈值。V2.1 将 sigma/tau 的选择目标统一为最终 60 帧 ES；
V2.0 在这里仍使用公共 50 帧窗口，新的运行不会沿用旧校准结果。
预先固定轮数后才评价确认集。所有轮次的监督均重新生成，不直接复用旧标签。
V2 权重和特征 schema 与 V1 不兼容，加载时明确拒绝；`--resume` 仍要求代码和设置完全匹配。

## 训练诊断边界

V2.1 的小样本拟合仅取 Train 事件，在 CPU 上用独立随机状态训练一个临时 controller，
关闭 weight decay，不修改正式模型、超参数、训练随机序列或 Dev 筛选门槛。
末层零初始化保持 Keep 相对收益初始为零；隐藏层依旧随机初始化，不存在全网对称初始化的问题。
因此初始 MSE 等于三个动作目标收益的平方均值，不适用分类任务的 ln(C) 初始损失规则。

诊断基线只有 Train 均值、分阶段 Train 均值和固定 ridge=1 的线性回归；系数不在 Dev 拟合。
它们只在已记录单次干预分支上评分，不参加部署选择，也不具备完整策略性能的含义。
拟合过程中记录的是更新后的全 Train/Dev MSE，单独保留更新前 minibatch MSE。
参数变化是实际 AdamW step 前后之差；零权重的相对更新比值为 null，不用 epsilon 制造巨大比值，
也不把课程中的经验比例当成所有层都必须满足的阈值。

每个场景有两个事件，离线诊断只做描述性均值，不将这些事件当独立样本计算显著性。
收益为零和小样本过拟合成功都不代表可泛化改进；最终判断仍使用完整 Dev 策略筛选及独立确认集。

## 基线检查边界

每次运行在一个 Calibration 场景上比较 Keep 适配器与同权重、无任何 hook 的固定版本模型，
记录 `baseline_adapter.json`。两边都使用同一纯 PyTorch attention 后端。
该检查能发现包装层改变 baseline 的问题，不能替代与官方 NATTEN 后端及完整官方验证集的对照。

## 两类评价不要混用

`diagnostic.jsonl`：只改某一个决策，回答干预是否存在收益。标签/最佳分支是诊断 oracle，不能声称可部署。

`evaluation.jsonl`：策略在每次更新时间自主决定，不搜索未来最优分支。普通/冲突组固定来自原始 Keep 模型在 4 秒时的残差，所有方法使用同一组场景。

`summary.json`：按 scene 进行配对 bootstrap。单事件表每个场景只有一个事件；不把两个更新当独立场景。
正的改善量等于 `ES_keep - ES_method`，同时报告组内数量和 95% CI。

## 指标定义

ES 对轨迹向量按 `sqrt(有效帧数)` 归一化：

`sum_k p_k ||z_k-y|| - 0.5 sum_kl p_k p_l ||z_k-z_l||`。

minADE6 对六模式取最小平均距离；minFDE6 取最小终点距离；1-mode 指标用最高概率模式；miss threshold 为 2 米。
`b_minFDE6` 取最小 FDE 的模式再加 `(1-p)^2`。
固定上游代码实际对 `FDE + (1-p)^2` 的总和取最小值，另存为 `b_minFDE6_upstream`，避免混淆。
目标有效性掩码在同场景各分支完全相同。空目标会失败并保留错误，不静默丢弃。

## 继续 / 转向判断

1. 保留历史在普通场景是否有益？若全清空普遍最好，先核对官方基线、坐标、训练适配。
2. Drop-worst 是否优于同数量/同年龄 Random-drop？
3. Controller 是否在独立场景超过校准规则，同时没有明显损伤普通场景？
4. 若只观察到 oracle 收益，仍需证明可预测的动作选择能泛化。

本阶段没有构造人工冲突、遮挡或意图标签；high_conflict 只是新观察与旧预测的残差分组。
完整的 RSI 论证还需要固定监督与普通难例训练的计算预算匹配对照。`--rounds 3` 本身不提供该论证。
V1 的确认集结果已经参与研究判断；相同场景上的 V2 重跑是探索性比较，正式确认需另用未查看的验证场景。
