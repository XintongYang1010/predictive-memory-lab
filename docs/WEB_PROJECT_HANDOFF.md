## 1. 这个项目究竟想解决什么

核心问题是：**在有限记忆下，模型能否保留暂时看不见的对象状态；新证据到来时更新该对象，同时不破坏其他仍有效的历史？**

具体想象：A 与 B 曾分别向不同方向运动，随后被遮挡。现在的画面无法区分两种早期历史，模型需要依靠记忆预测它们将出现在哪里。若 A 重新出现并改变运动，模型应修正 A，继续保存 B 的旧状态。干扰物出现和经过更长时间，都可能使这个过程失败。

因此需要分开检查三件事：

- **保留：** 早期有用信息是否在遮挡和干扰后仍可使用？
- **更新：** 新证据能否改变已过时的状态？
- **避免干扰：** 更新 A 会不会错误改写 B？

这不是已经解决的视觉世界模型，也不是已经证明的新 memory 算法。研究动机与某个实现是否有效，是不同层次。

## 2. 为什么经历 V1–V4，再到 V5

V1–V3 从 RealMotion 的旧预测 bank 出发，检验何时保留、重建或重置历史。已经跑过的 V2.1/V3 没有取得可靠部署收益。这个设定也不能直接回答长历史下对象状态如何持续存在。

V4 改成可控数值状态任务：直接提供可见对象的身份、位置和速度，比较窗口、FIFO、GRU、对象状态与解析跟踪。它把检测和对应困难拿走，先研究保留、更新与干扰；已知身份和恒速先验很强，不能把其中效果当作视觉记忆证据。详细背景见 [V4 协议](STATE_MEMORY_V4.md) 和实验时间线。

V4 的独立结果分支已记录 A100 Slurm615 正式三种子实验，T48 的 slot 对 GRU 有收益，但 T96 仍有漂移；外层与容器的 GPU UUID 不一致，资源绑定核验失败。旧“尚未正式 A100”描述已过时。该分支只有小型报告/日志，约343MiB原始完整包当时存于 Slack/服务器，**本次未将其检查点全包镜像到 GitHub**；历史地址和 SHA 见 [资产索引](WEB_PROJECT_ARTIFACT_INDEX.md)。

V5 再把输入换成 RGB，并使用冻结的官方 I-JEPA 编码器。这样开始接触真正的视觉表示困难，却也引入了一个更靠前的门槛：**在讨论记忆前，模型是否能从视觉特征读出基本的位置与运动？**

## 3. V5 的原设计与真实执行路径

原方案的概念路径：

```text
受控世界与合法 RGB 观察
  → 冻结 I-JEPA，逐帧编码
  → 空间 token / 原方案 4×4 池化
  → 时间预测器 P0 与历史读取
  → 有限容量的 recent / exact / compressed memory
  → 未来特征预测
  → 保留、干扰、更新及历史交换/清零评价
```

原方案准备了三种 writer（additive、gated additive、gated delta）× 两种 reader 条件 A0/A1/B0/B1/C0/C1，以及 full-history、recent-only、等字节 FIFO 和固定 writer 的 reader-only replay。详细定义以 [V5 协议](VISUAL_MEMORY_V5.md) 与代码为准。

**原完整链路没有跑通。** 首轮完成真实权重加载/profile 和特征 probe，但原 pooled 位移 probe 未过预设门槛，因此原 P0/history gate、六组 memory 主比较和原 reader-only replay 没有启动。

后续 V5.1–V5.8 是为解释这个前置失败开展的诊断，其中确实训练过诊断 reader、做过原型 memory/update 对照；这些不等于原六组架构训练已完成。V5.8 的实际路径尤其简单：

```text
同一批已缓存 raw I-JEPA 特征
  → 五种受控空间操作 R / H / BR / DR / DBR
  → 固定源图像特权 ROI + 固定二维 cosine 匹配
  → 位移、错向、正确位置排名和代价面
```

这里没有训练、原 P0 或原 memory writer。ROI 利用源图像颜色定位对象，是诊断特权；它并没有解决任意视频中的检测与对象身份。

## 4. 数据与指标应当怎样理解

原 V5 是合成 RGB 机制任务：两个带纹理目标和干扰区域，有受控的可见/遮挡日程及更新事件。成对世界保持近期观察等条件一致，让早期历史影响正确答案。没有声称覆盖真实视频、移动相机或任意物体。

V5.8 复用已反复查看的 **256 个 Dev world、512 个 episode、1024 个对象查询**。同一 world 的变体和对象不是独立世界。原 Test 没有开启；V5.6 的 Fresh64 是另外的对象组合确认，不能称为原 Test 或所有后续分析的独立确认。

| 名词 | 直观含义 | 容易误读的地方 |
|---|---|---|
| encoder | RGB → 空间特征 | 单图预训练不自动保证小位移的跨帧对应 |
| pooling / sampling / reconstruction | 平均、减少网格点、在点间重建 | 三者不同；V5.8 的 D 仍合并采样和双线性重建 |
| reader / matcher | 从特征读出目标状态或位移 | 本轮固定 cosine 与原训练型 reader 不是同一个模块 |
| writer | 把新信息写入有限记忆 | 当前 V5.8 路径没有它 |
| dx / dy RMSE | 预测位移与真实位移之差，单位像素 | 水平改善不意味着纵向或联合指标改善 |
| wrong sign | 非零预测朝真实运动反方向 | 零输出单列，不能偷偷混进或移出分母 |
| GT rank | 最近真实位移的候选在匹配代价排序中的名次 | 是离散候选排名，不是连续真值的可恢复信息量 |
| oracle / privileged control | 为诊断额外提供真值或定位信息 | 只能用于定位上界，不能当可部署方案 |
| bootstrap CI | 按 world 成组重采样的不确定区间 | 已知 Dev 上的探索区间，不等于独立确认或因果证明 |

## 5. 截至 V5.8 可以说什么

1. **当前空间操作与匹配器之间有可重复的失败。** 密集同相位网格上，4×4 平均比 2×2 平均差；对这两种密集场进行粗采样重建，都进一步损害匹配。共同内点上仍成立。
2. **两种操作存在交互。** 粗网格上 4×4 平均反而优于 2×2 平均，不能归纳为“一切平滑都坏”，也不能分配模块责任百分比。
3. **局部细节访问值得研究。** 先前对象区域对照、当前 raw 与 pooled 的差距提供了动机，但颜色 ROI/额外访问是强条件。
4. **原始表示与读出仍不完美。** 原 raw 仍有位移低估、排名和残余错误，不能说取消 pooling 就修复原任务。
5. **原 memory 收益尚未建立。** 还需在确实需要历史的任务上、固定预算和其他模块，验证相对简单记忆基线的收益。

不能说：encoder 已被证明坏了；约 90% 的运动信息被丢失；降低 latent MSE 就等于理解运动；某张可视化更清楚就证明更好；当前 bad case 证明 Cambrian-S 错误；所有旧 batch/帧序疑点都仍未排除。后续精确回放和批次补验已排查了多项实现疑点，见时间线。

## 6. 为什么现在先读论文

继续扫描滤波宽度、插值和网格，可能主要优化这个两帧诊断 matcher。现在已有足够具体的现象，应该先决定：**压缩时保存什么，哪些细节未来可能有用，读出如何识别可信的对象对应？**

优先阅读 Cambrian-1 的空间聚合、V* 的目标引导细节搜索，再用 TAPIR 理解对应与定位不确定性；Thinking in Space 提供中间状态诊断范式，FeatUp 提供空间重建思路。用户已读的 Cambrian-S 应特别检查 surprise 与未来可用性、写入时未知查询、KV 存储预算等问题。详见论文路线文档。

候选假设：**写入时不知道未来查询，在固定存储字节下，按对象对应/定位的不确定性保留局部细节，是否比仅按整帧 surprise 分配记忆更能维持遮挡后状态？**

这是研究假设，没有完成新颖性检索或验证。低 surprise 不必然意味着局部细节不重要；但保存高不确定性区域也可能只保存噪声，必须设置会推翻它的实验。

## 7. 下一轮实验的启动条件

先写一页方案，包含：固定坏例揭示的现象；拟改一个主要机制；明确的收益和失败预测；输入/存储/计算预算；基线；FIT/选择集/新确认集边界。

建议回到历史必要的遮挡、重现与更新任务，固定 encoder、reader 和字节预算，对比 uniform/FIFO、surprise、对象最新状态等简单策略与新策略。使用真实位置/身份或不压缩特征作为单独的诊断参照，而非隐藏地给新方法更强输入。报告对象状态准确性、变化对象恢复、未变化对象干扰、历史交换/清零结果及实际开销。

同一特征场的精确平移 versus 采样后重建平移仍是尚未执行的便宜控制。只有它会改变方法选择时才优先做；无需把每个旧坏例都解释完才读论文。现有 Dev 适合形成假设，正式确认需要没用于反复选方案的数据。
