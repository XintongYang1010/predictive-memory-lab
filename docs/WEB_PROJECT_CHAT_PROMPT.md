# 发给网页端的提示词

请通过我授权的 GitHub 连接读取私有仓库 `XintongYang1010/predictive-memory-lab`，分支 `handoff/web-project-review-20261010`。先读取 `docs/WEB_PROJECT_FULL_CONTEXT.md`；再按需要读取其中链接的图像、各轮报告、原始 CSV/JSON 与代码。最新状态是 V5.8 完成，不要只读仍保存早期计划的旧文档。若不能访问私有仓库，请明确说明，我可以从同一 GitHub Release 下载单文件讲解或阅读包提供给你；不要假装已读。

我的目标是先从头理解自己的项目，跟上之后，再由你带着分析 bad case、阅读论文并讨论下一步方案。请用中文，循序渐进，每次只推进一个模块或一个坏例；先直觉与具体例子，再补术语、公式和源码。每段结束留一个简短的复述/判断问题，等我回答后继续。不要一次给我完整长篇综述，也不要直接安排新一轮大实验。

请按这个顺序教学：

1. 先讲项目想解决的保留、更新与干扰问题，以及为何需要历史；用两个对象的遮挡例子解释。概括 V1–V4 到 V5 的演变。
2. 讲 V5 输入、冻结 I-JEPA、空间 token、pooling、P0、reader、writer 和预算，区分原设计与真正执行过的诊断路径。
3. 讲首轮为什么停止，V5.1–V5.8 每轮回答了什么；不要把诊断 reader 的训练说成原 memory 已训练成功，也不要复活已排查的 batch/帧序疑点。
4. 带我逐个看固定案例 844/1 A、891/1 B，再用 761/1 作反例。先读两帧 RGB 和真实运动，再读预测、候选代价面与 GT rank。解释 R/H/BR/DR/DBR 只改变了什么、仍混合了什么，哪些因果解释有证据，哪些仅是假设。
5. 我跟上之后，把每个问题映射到论文模块。优先 Cambrian-1、V*、Thinking in Space；补 FeatUp、TAPIR，并联系我正在读的 Cambrian-S §4 与 Appendix F.2。阅读论文原文后再讲技术细节；区分论文证明的结果与迁移到本项目的推断，注意原图访问、特权 ROI、KV 与 raw feature、时序因果性及总存储成本。
6. 最后和我共同写一页下一步研究方案：一个主要假设、应修复的坏例、可推翻它的结果、同预算基线、必要诊断和新的确认数据。现在尚未证明原 memory 有效；不要先把某个方向称为创新。

请从第 1 步开始，先让我真正理解任务，不要急着把全部步骤讲完。每个关键实验结论附具体 GitHub 文件或图表路径；若发现资料不足或矛盾，请指出缺口，不要补造实验。
