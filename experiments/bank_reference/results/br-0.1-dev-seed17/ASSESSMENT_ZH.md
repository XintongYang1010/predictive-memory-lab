# 结论：开发对照已跑完，但这个残差 bank 还不是可信的论文比较

这次完成了独立 BR-0.1 代码、11 项因果/接口测试、原 A1/A2/A6 的 1,152 项误差对账，以及固定 K=4/16/64 的 CPU 开发实验，实际运行 160.3 秒。没有恢复原始数据、使用 GPU、修改旧 V6 科学门槛或打开 FINAL/test。

**目前最重要的结论有两层：确实找到了“被未来读取的旧记忆反而有害”的可核对坏例；但整个 bank 的读取器和训练信号太弱，不能把这些结果称作原 WR/PaFu 论文的失败，也不能据此宣布新的论文主线。**

## 实际使用了什么

现存文件有 EXACT、NEWPATH、CHANGE 各 32×799 步的 R/O/W/key/A2 gate；没有完整 Z、原观测、动作、连续 pose、RGB。manifest 中存在 Z/EPS 的 hash，不等于这些数组仍然存在。因此这是 **L0 派生的冻结残差诊断**。

固定原 A 索引 0..22 训练，24..31 开发评估，删去边界索引 23，避免相邻 CHANGE 配对共享训练/评估来源。共 69 训练流、24 开发流、3 排除流。内部开发集已在旧研究中使用，仍不能叫独立确认；八个开发 A 簇之间也有相邻 CHANGE 源依赖。

三个 bank 使用同一个先预测后写入、相同 key 的 masked-mean 读取器，R=4，K 分别为 4/16/64；同一 K 使用相同预留动态状态上限。实际字节、未用预留和模型参数另外报告，未声称实际成本完全相等。A2 是来自完整 Z 的冻结门轨迹重放，属于单独参照，不能称和 bank 输入等价。

## 整体结果不支持直接继续堆机制

下表均为原始标准化残差 MPE，越低越好，保留合并 EXACT+NEWPATH。

| K=64 的方法/参照 | 保留 POST | CHANGE POST |
|---|---:|---:|
| FIFO bank | 1.367977 | 1.332790 |
| WR-inspired bank | 1.337642 | 1.367625 |
| PaFu-inspired bank | 1.319384 | 1.340927 |
| 不使用记忆 | 0.989542 | 0.946773 |
| 全部历史同 key 均值参照 | 1.062410 | 1.294315 |
| A2 冻结门重放参照 | 0.927914 | 0.936854 |

WR/PaFu 在 K=64 的保留误差比 FIFO 低，但 CHANGE 没有同样改善；**三个 bank 都明显差于不使用记忆**。连全部历史同 key 均值也差，因此不能简单把失败归给容量不足或选择器。这个朴素读取器没有 A1/A2 的保守更新；噪声、同 key 上下文差异和陈旧记忆各自贡献多少，本轮没有隔离。

PaFu 的监督还非常稀疏：每个 K 固定考察 276 个训练父状态，未来六步实际把注意力放在历史候选上的状态只有 **3 / 4 / 39** 个。未命中的查询被正确跳过，没有伪造均匀注意力标签。每个学生虽然按固定 100 epoch 完成，仍不足以支撑稳定的算法优劣比较。教师仅有 future 组，也是明确的适配退化。

## 一个已核对的坏例：读到，不等于有用

最大局部 regret 来自 **K=16 PaFu、CHANGE、源索引 31、原时间 464**。这是事后展示的最大案例，不是代表性平均结果。

- 策略保留了旧世界中观察序号 13、key=195 的条目，却删除了刚进入历史区的序号 459、key=210 条目。
- 后续六步 query key 为 `[203,203,195,195,195,195]`。
- 在完全相同的 17 个候选和 4 个 recent 条目中，只改变删除哪一个，策略的六步 MPE 为 **3.118468**，oracle 删除旧 key=195 后为 **0.810922**，局部 regret **2.307546**。
- 对这个已保存父状态再读取实际 future-attention：教师把 **100%** 的历史候选注意力概率分给了恰好应删除的旧 key=195 条目。学生给它约 4.99%，给被删条目约 0.276%。

因此，**即使这个读取器的注意力被完美预测，注意力目标也会偏爱一个对后续损失有害的旧条目**。这比“学生没学好”多提供了一条可核对的机制线索。但它只证明本残差读取器中的 attention/utility 分歧；原 PaFu 使用不同的模型与读取结构，不能直接外推。

本轮共枚举 864 个父状态的所有单条删除，oracle 只允许从同一 K+1 候选中删一条，recent 完全相同，后续六步冻结 bank、不写入新样本。它是局部特权诊断，不是全局最优在线策略。某个父状态零 regret 也不代表之前没有误删关键历史。

## 下一步边界

本轮按固定配置停止，没有根据结果改 key、读取器、采样点、epoch、容量或种子。真正有价值的后续验证应使用已有可用的历史敏感预测器/完整因果 token，确认这种 attention/utility 分歧仍然存在，且不是残差均值读取器本身造成；然后才讨论新选择目标。当前结果适合带去讨论问题与实验设计，不适合声称两篇论文已经被击败。
